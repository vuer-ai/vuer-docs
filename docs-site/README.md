# Vuer documentation with DreamLake Dockit

The original `docs/` MyST/Sphinx sources and `src/vuer` Python source are preserved. This standalone site uses `@dreamlake/dockit` 0.2.14; a deterministic converter translates authored pages, navigation directives, local assets and Python API references without importing Vuer or running example servers.

```sh
cd docs-site
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm ci
PYTHON=.venv/bin/python npm run build
npm run preview
```

Build output is `docs-site/dist/client`. Generated pages are disposable: edit the authored Markdown under `docs/`, then rebuild. Python API pages are generated by the pinned `dreamlake-ai/autodoc-py` dependency. The site publishes Markdown twins and `/llms.txt`, uses Pagefind for search, and keeps embedded interactive Vuer scenes.

Production uses `main`; historic `docs/<tag>` branches retain the corresponding upstream source commit with this tooling overlaid. `archive/<tag>` refs preserve unmodified source snapshots. Netlify deploys documentation branches individually. The version selector reads production `/versions.json`, with CORS enabled so historic branch sites always discover newly published versions. Never force-push archival refs.

## Release and archive workflow

For an existing release, start from its exact `archive/<tag>` commit, overlay the tracked `docs-site/` and `netlify.toml` files from the migration commit, and create `docs/<tag>`. Build with `BRANCH=docs/<tag>` so installation snippets and the version badge name that release. Each branch retains its corresponding Python implementation; API generation never substitutes the latest source. Early tags without `docs/` use their README as the homepage; RST sources are converted when present, and the pre-Vuer `tassa`/`nerf_vuer` packages are detected.

Source branches: https://github.com/vuer-ai/vuer-docs/branches

Preserved rendered builds: https://vuer-docs-archive.netlify.app (archive capture status is maintained separately; the original ReadTheDocs origin remains the fallback).

Existing `/en/latest/<page>.html` and `/en/stable/<page>.html` links redirect to their migrated routes. Other `/en/*` requests proxy to https://vuer-py.readthedocs.io/en/ so old release links remain available while rendered snapshots are captured.

Netlify production tracks `main`; documentation branch deploys use the same checked-in build configuration. Publish only after the build, local link audit and browser inspection pass. Keep `public/versions.json` URLs synchronized with verified branch deployments. Preserve prior deploys and source refs; never force-push `archive/*` or replace an already published release snapshot.

The converter writes generated MDX and Markdown downloads during each build. Do not commit those generated files. Vike must be able to discover generated `pages/`, so it is intentionally not listed in `.gitignore`.
